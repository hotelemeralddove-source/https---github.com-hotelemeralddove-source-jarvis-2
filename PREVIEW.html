2 · HOW IT DRAWS — AND HOW IT EDITS

THE DRAWING LANGUAGE

  • Each subject is a list of primitives in 0..1 space: ellipse, rounded rect, polygon, bezier
  • Painted with QPainter at any resolution — 900×620 or 4K, same code
  • No assets, no downloads, no GPU, no network. ~3 ms per frame
  • 10 subjects: elephant, cat, dog, house, tree, flower, car, robot, fish, sun
  • Aliases work: "aane", "haathi", "pilli", "maram"

THE DOCUMENT (WHY EDITING WORKS)

  • State = {subject, accent, scale, dx, dy, rotate, extras, history}
  • "make it purple and bigger" → changes 2 fields → re-renders. Nothing is regenerated blindly
  • Undo is a snapshot stack — free, instant, always exact
  • The easel window has a text line: same edits by typing
  • Saving is additive: _v2, _v3 — it never overwrites your file

THREE BUGS THIS FEATURE HAD — CAUGHT, FIXED, TESTED

  • "draw an elephant" drew the wrong animal. The article regex ate "an" and then hit a space, so the subject came back empty and it fell back to the default. Fixed with an?\s+|the\s+ and locked by test_art.py check 6
  • "make it purple, add a sun" replaced the elephant with a sun. Subject matching keyed on the word "make". Now a subject only changes when it is the grammatical object ("draw a cat", "turn it into a house")
  • Scenery scaled with the subject. The sun flew off the canvas. Decorations now render in canvas space, before the subject transform

A BUG THE FIRST PRESET LIST HAD

  • fetch, time, git were pointed at npm packages that do not exist — and mcp-server-fetch on npm is 0.0.1-security, npm's placeholder, not the real package
  • They are Python servers upstream. Correct runner: uvx mcp-server-fetch
  • With npx the process exits instantly and the app still looks fine — the tool just never appears. That failure mode is now forbidden by test_mcp_presets.py
